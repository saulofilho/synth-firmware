Four slash commands

/firmware-new, /firmware-phase, /firmware-check, /firmware-release — scaffold, advance a phase, lint the chip rules, cut a release.

Chip-rule lint

After an edit to firmware C, it flags float/double, 64-bit division and ROM-range constants early. Advisory — the build is the authority.

It respects the chip

The rules the AC791N enforces

No FPU, a tight audio budget, and a pool that's nearly full. The plugin writes code that respects them from the start.

  chip-rules.md
# integers only — no FPU, no soft-float
forbid  float, double            // → link fails
use     Q15 levels · Q12 gains · 32-bit phase
forbid  64-bit / and %           // no __udivdi3

# the audio interrupt
budget  app_audio() 256 frames / 5.8ms
target  < 2.9ms   ✓ off costs nothing
never   flash · screen · wait inside audio

# boundaries
hal     hardware registers only through hal/
accept  both flash ids 0x856014 · 0xB36014

saulofilho / synth-firmware

A Claude Code plugin for building M-VAVE FM-1 firmware on the Felucca platform. GPL-3.0-only, matching the GR!MM / Felucca lineage it builds on.

Repository ↗ COQUÍ (example) ↗ FM-1 Firmware Hub ↗ Claude Code plugins ↗

Honest scope: the plugin encodes the FM-1 / Felucca method at high fidelity — phases, chip rules, toolchain, release. It does not generate the DSP for a new sound engine; that stays real engineering. It accelerates the skeleton, keeps the constraints, and gets the release right.
